## 2.  elevator pitch（30 秒版）

基于 **LangGraph + LangChain** 自研 **YAML 声明式多 Agent 编排引擎**，面向医疗健康场景实现意图识别、动态路由、工具调用与 RAG 问答；配套 **Langfuse 全链路追踪**、PostgreSQL 持久化、数据清洗与 Embedding 批次化平台，支撑从对话服务到知识库生产的完整闭环。

## 3. 业务背景与领域知识

### 3.1 业务场景

| 场景 | 说明 | 对应 Agent / 模块 |
|------|------|-------------------|
| 血压管理 | 记录、查询、修改血压数据 | blood_agent、blood_pressure_tool |
| 安全边界 | 医疗合规回复、风险话术 | 安全边界 Agent（历史版本） |
| 数据记录 / 点评 | 多类型健康数据录入与 AI 点评 | record_agent、数据点评 Agent |
| 知识问答（QA） | 基于向量库的案例召回与回复 | QA_agent、rag_node |
| 科普文章推荐 | 按疾病名召回文章并追加链接 | retrieval_node_v2 |
| 知识库运营 | 原始素材 → 清洗 → Rewritten → Embedding | data_cleaning、batch_jobs、scripts |

### 3.2 典型用户链路（v6.3 主流程）

```
用户消息
  → builder_prompt_context_node（拉取用户血压等上下文）
  → optimization_agent（意图识别 + 词干提取，输出 intent/confidence）
  → rag_node（向量召回相似 QA 案例，注入 prompt_vars）
  → 条件路由：
       intent=blood_pressure 且 confidence≥0.8 → blood_agent
       intent=qa 或 confidence<0.8            → QA_agent（兜底）
  → 返回 JSON 结构化回复 → 前端展示
```

## 5. 系统架构（分层）

```
┌─────────────────────────────────────────────────────────────┐
│  接入层：FastAPI Routes（chat / flows / data-cleaning / …）   │
├─────────────────────────────────────────────────────────────┤
│  编排层：FlowManager → GraphBuilder → CompiledGraph           │
│          NodeCreatorRegistry（agent/function/rag_agent/…）   │
├─────────────────────────────────────────────────────────────┤
│  Agent 层：AgentFactory → AgentExecutor（ReAct 内层图）       │
│          ToolRegistry（血压/用药/症状/健康事件）               │
├─────────────────────────────────────────────────────────────┤
│  数据生产：pipeline（清洗/改写队列）+ scripts（Embedding 导入）│
├─────────────────────────────────────────────────────────────┤
│  基础设施：ProviderManager / Langfuse / PostgreSQL+pgvector  │
└─────────────────────────────────────────────────────────────┘
```

### 5.1 核心类与职责

| 组件 | 职责 | 路径 |
|------|------|------|
| FlowDefinition | YAML 流程声明（nodes/edges/entry_node） | domain/flows/models/definition.py |
| GraphBuilder | 构建 StateGraph，挂载条件边 | domain/flows/builder.py |
| FlowManager | 扫描、缓存、预加载、compile 图 | domain/flows/manager.py |
| FlowState | 节点间状态（message、trace_id、edges_var…） | domain/state.py |
| AgentFactory | 组装 LLM + Prompt + Tools | domain/agents/factory.py |
| ProviderManager | 多模型供应商 YAML 配置 | infrastructure/llm/providers/manager.py |
| RuntimeContext | 请求级 token/session/trace 上下文 | domain/tools/context.py |
| ApplicationBootstrap | 启动编排（供应商→工具→流程预加载→队列） | app/bootstrap.py |

### 5.2 节点类型（可扩展）

| type | 创建器 | 用途 |
|------|--------|------|
| agent | AgentNodeCreator | LLM + 工具 ReAct Agent |
| rag_agent | RagAgentNodeCreator | 向量召回并写入 prompt_vars |
| function | FunctionNodeCreator | 纯业务函数节点（用户信息查询、RAG 检索等） |
| em_agent | EmbeddingNodeCreator | Embedding 生成节点 |

## 6. 功能模块清单（简历职责素材）

### 6.1 多 Agent 编排引擎（核心）

- YAML 声明式定义流程，**10 套 flow.yaml**（medical_agent v4~v6.3、pipeline、embedding 等）
- 动态路由：从静态硬编码 → 注册式 NodeCreator + 条件边（`intent == "blood_pressure" && confidence >= 0.8`）
- 流程预加载：bootstrap 阶段按配置 preload，降低首请求延迟
- 前端可选后端流程（Session 绑定 flow_key）

**简历关键词**：LangGraph、声明式编排、动态路由、状态机、可配置工作流

### 6.2 对话与 API

| 路由文件 | 能力 |
|----------|------|
| chat.py | /chat 主对话，Langfuse trace、RuntimeContext、JSON 回复解析 |
| flows.py | 流程列表、预览 |
| login.py / users.py | 用户与 Token |
| blood_pressure.py | 血压 CRUD API |
| knowledge_base.py | 知识库管理 |
| data_cleaning.py | 数据清洗全链路 API（970+ 行） |
| batch_jobs.py | 通用批次任务创建 |
| articles.py | 科普文章 |

### 6.3 业务工具（Function Calling）

| 工具 | 文件 |
|------|------|
| 血压 | blood_pressure_tool.py |
| 用药 | medication_tool.py |
| 症状 | symptom_tool.py |
| 健康事件 | health_event_tool.py |

装饰器 `@register_tool` 自动注册；工具调用对接 Langfuse 追踪（Issue #17）。

### 6.4 RAG 与知识库

- **向量检索**：pgvector + vector_db_search，支持多表、关键词混合、min_results 兜底
- **RetrievalNodeV2**：QA 案例召回 + 科普文章按疾病名检索
- **scripts 工程**：Embedding 导入（单线程/并行）、Feishu Excel → DataSet、RAG 数据创建流程
- **QA 场景文档**：43 篇独立场景记录（cursor_docs/012802-QA场景独立记录/）

### 6.5 数据清洗与 Embedding 批次平台

- **Step1**：原始素材入库、元数据归一化、UK 逻辑、路径树管理
- **Step2**：LLM Rewritten 改写，asyncio 内存队列 + 4 消费者协程
- **批次框架**：BatchJob / BatchTask 表、通用 job_type Handler、批量 Embedding 创建 API + 前端调试页
- **数据模型**：DataSets、DataSetsItems、DataItemsRewritten、RewrittenBatch、EmbeddingRecord 等

### 6.6 可观测性（Langfuse）

- Trace 上下文：ContextVar 传递 trace_id，API 层强制传入
- 路由后 traceId 一致性修复（Issue #10 关键卡点）
- 多意图路由监控、工具调用 Span、流程节点 Tracename
- LLM 思考过程记录（Issue #8）

### 6.7 会话与上下文

- Token / Session 双层缓存（PostgreSQL 表 + 内存 ContextManager）
- 启动时 load_context_cache（上限 10000 条）
- prompt_vars / edges_var / persistence_edges_var 分层变量通道

## 8. 技术难点与 STAR 素材（面试 / 简历深化）

### 8.1 动态路由架构重构

| 维度 | 内容 |
|------|------|
| **Situation** | MVP 阶段路由逻辑硬编码在代码中，新增 Agent 需改核心路由文件 |
| **Task** | 支持 YAML 配置流程、节点可复用、前端可选流程 |
| **Action** | 设计 FlowDefinition / GraphBuilder / NodeCreatorRegistry；条件边 + ConditionEvaluator；FlowManager 扫描预加载 |
| **Result** | 10+ 流程版本迭代（v4→v6.3）；新增 Agent 仅需 YAML + prompt 文件 |

### 8.2 Langfuse Trace 一致性

| 维度 | 内容 |
|------|------|
| **Situation** | 路由后子 Agent 的 traceId 与入口不一致，无法关联完整调用链 |
| **Action** | ContextVar 传递 trace_id；start_as_current_span + trace_context；工具与 LLM 回调统一挂载 |
| **Result** | 多意图路由可观测；Issue #10 关闭 |

### 8.3 LLM 输出 JSON 不稳定

| 维度 | 内容 |
|------|------|
| **Situation** | 数据清洗 Step2 模型返回有时非 JSON，导致流水线中断 |
| **Action** | Agent 输出统一 JSON Schema；前端支持 JSON 字段提取；清洗模块增加结构校验与重试 |
| **Result** | 数据清洗 Step2 可批量运行（Issue #41） |

### 8.4 RAG 融合与 QA 知识库

| 维度 | 内容 |
|------|------|
| **Situation** | 纯规则路由无法覆盖开放问答；需要相似案例提升回复质量 |
| **Action** | optimization_agent 提取 intent/keywords → rag_node 向量召回 → 条件路由 blood/QA；43 场景 QA 案例清洗入库 |
| **Result** | medical_agent_v6.3 融合流程；「RAG 初步见到成效」提交记录 |

### 8.5 Embedding 批次化

| 维度 | 内容 |
|------|------|
| **Situation** | 知识库规模大，单条 Embedding 无法支撑运营 |
| **Action** | 抽象 BatchJob 通用框架 + job_type Handler；批量创建 API + 前端；scripts 并行导入 |
| **Result** | PR #42 大合入；批量 Embedding 测试完成 |

## 16. 面试高频问题预备

| 问题 | 回答要点（素材位置） |
|------|----------------------|
| LangGraph 和 LangChain Agent 区别？ | 外层 StateGraph 管多节点协作；内层 create_agent 管单 Agent ReAct（factory.py） |
| 如何实现动态路由？ | EdgeDefinition.condition + ConditionEvaluator + state.edges_var（flow.yaml v6.3） |
| RAG 怎么做的？ | optimization 提取关键词 → rag_agent 向量检索 → 注入 prompt_vars → 下游 Agent |
| Trace 怎么串起来？ | ContextVar trace_id + Langfuse start_as_current_span（langfuse_handler.py） |
| 如何保证 LLM 输出稳定？ | JSON 格式约定 + Pydantic 校验 + 清洗模块重试（Issue #41） |
| 流程怎么扩展？ | 新增 flow 目录 + YAML + prompts，NodeCreatorRegistry 注册新 type |
| 最大的技术挑战？ | 动态路由重构 / Trace 一致性 / RAG 融合（§8） |
