# 需求说明
- 参考之前的回话接口，新写一个独立的API对外暴露，可以用这个API进行回话
- 写一个简单的工作流。第一版本只要一个节点，写单间的提示词即可
- API不需要负责的session之类的，减少这个API的负责度，只要能根据用户的Query，进行简单的回复。


# 详细设计

## 1. 目标与边界

**目标**：对外提供一条「无 Session」的轻量会话通路，用于华院侧首次联通验证——调用方传入用户 Query，系统走一个单节点工作流，返回模型回复。

**边界（V1 不做）**：
- 不创建 / 校验 Session、Token 上下文缓存
- 不依赖 `/login/session`、`validate_context_cache`
- 不维护多轮对话历史（请求体不接收 `conversation_history`）
- 不绑定医生信息、患者档案、工具调用、RAG 检索
- 不改动现有 `/api/v1/chat` 行为

**与现有聊天接口的关系**：

| 维度 | 现有 `/api/v1/chat` | 本设计新接口（建议） |
|------|---------------------|----------------------|
| 前置条件 | 需 login + session 缓存 | 无 |
| 入参 | message + session_id + token_id + history… | 仅 query（可选 trace_id） |
| 流程选择 | 由 session 中的 flow_key 决定 | 固定绑定本流程 |
| 职责 | 完整业务会话 | 联通与最小回复验证 |

---

## 2. 总体方案

沿用现有「API → 编译流程图 → `ainvoke` → 取 AI 回复」链路，但去掉 Session/Token 装饰与上下文拼装。

```
调用方
  │  POST /api/v1/huayuan/chat
  ▼
新路由（独立模块）
  │  构造最小 FlowState（仅当前用户消息）
  ▼
FlowManager.get_flow("huayuan_simple_agent")
  │
  ▼
单节点 agent（简单系统提示词 + LLM）
  │
  ▼
从 flow_msgs 取最后一条 AIMessage → 返回 response
```

---

## 3. API 设计

### 3.1 接口定义

- **Method / Path**：`POST /api/v1/huayuan/chat`
- **Tag**：`华院联通`
- **鉴权**：V1 可不做业务鉴权（与「降低复杂度」一致）；若网关已有统一鉴权，本服务内仍不校验 token/session。

### 3.2 请求体

```json
{
  "query": "你好，请简单介绍一下你自己",
  "trace_id": "可选，32位小写十六进制；未传则服务端生成"
}
```

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| query | string | 是 | 用户本轮输入；空字符串返回 400 |
| trace_id | string | 否 | 便于日志与 Langfuse 串联；未传则自动生成 |

### 3.3 响应体

成功（200）：

```json
{
  "response": "模型生成的回复文本",
  "trace_id": "本次实际使用的 trace_id"
}
```

失败：
- `400`：query 为空或非法
- `500`：流程加载失败 / LLM 调用异常（detail 中给出简要错误信息）

### 3.4 与现有 Chat Schema 的差异

不复用 `ChatRequest` / `ChatResponse`（避免强制携带 `session_id`、`token_id`）。新建独立 Schema，例如：

- `HuayuanChatRequest`：`query`、`trace_id?`
- `HuayuanChatResponse`：`response`、`trace_id`

## 4. 工作流设计

### 4.1 流程标识

- **flow name / key**：`huayuan_simple_agent`
- **目录**：`config/flows/huayuan_simple_agent/`
- **描述**：华院联通 V1 单节点简单回复

### 4.2 节点与边（单节点）

```yaml
name: huayuan_simple_agent
version: "1.0"
description: "华院联通V1：单节点简单对话"

nodes:
  - name: simple_reply_node
    type: agent
    config:
      prompt: prompts/simple_reply.md
      model:
        provider: doubao
        temperature: 0.7
        thinking:
          type: disabled

edges:
  - from: simple_reply_node
    to: END
    condition: always

entry_node: simple_reply_node
```

说明：
- 节点类型使用现有 `agent`，与 `create_rag_agent` 等单节点写法一致
- V1 不挂 tools、不做条件分支
- 模型 provider 与项目默认配置对齐（如 `doubao`），具体 model name 可按环境配置补全

### 4.3 提示词（V1 极简）

文件：`config/flows/huayuan_simple_agent/prompts/simple_reply.md`

内容方向（示例，实现时可微调）：
- 角色：友好、简洁的助理
- 任务：根据用户当前问题直接回答
- 约束：不编造需要外部系统才能确认的事实；回答简短清晰
- V1 可不依赖 `user_info` / `doctor_info` 等占位符，避免与 Session 上下文耦合

---

## 5. 服务端处理流程

1. 校验 `query` 非空。
2. 解析或生成 `trace_id`。
3. 通过 `FlowManager.get_flow("huayuan_simple_agent")` 获取已编译图（启动时已 scan；未预加载则按需编译）。
4. 构造最小初始状态（不读 ContextManager）：
   - `current_message` = `HumanMessage(query)`
   - `history_messages` = `[]`
   - `flow_msgs` = `[]`
   - `prompt_vars` = 空或仅含必要字段（如 `current_date`）
   - `session_id` / `token_id`：可置空字符串或固定占位（仅满足 FlowState 结构，不参与业务校验）
   - `trace_id` = 本次 trace
5. （可选）创建 Langfuse handler，tag 标记为 `huayuan_chat`，与正式 chat 区分。
6. `await graph.ainvoke(initial_state, config)`。
7. 从结果 `flow_msgs` 中取最后一条 `AIMessage.content` 作为 `response`；若无 AI 消息，返回兜底文案。
8. 返回 `HuayuanChatResponse`。

**明确不做**：`@validate_context_cache`、从 session 解析 flow_key、拼装医生/患者 prompt_vars、解析 `plan_response`（本流程非 Plan-and-Execute）。

## 7. 调用示例

```bash
curl -X POST 'http://localhost:8000/api/v1/huayuan/chat' \
  -H 'Content-Type: application/json' \
  -d '{"query": "你好"}'
```

预期响应：

```json
{
  "response": "你好！我是助理，有什么可以帮你的？",
  "trace_id": "..."
}
```

---

## 8. 验收标准

1. 不调用 login / 不创建 session，直接 POST 即可拿到非空 `response`。
2. 现有 `/api/v1/chat` 回归不受影响。
3. 流程仅一个 agent 节点，提示词可独立修改而不改 API。
4. query 为空返回 400；LLM/流程异常返回 500 且有日志。
