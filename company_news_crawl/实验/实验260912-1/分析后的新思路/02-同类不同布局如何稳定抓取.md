# 同类不同布局：如何保障稳定抓取

问题：企业库里有一批「像平安一样简单」的站，但 **DOM/布局并不一致**，不能共用一个写死选择器。

## 三层模型

### 1) 站点族 site family（能力画像，不是像素）

进入 `list_with_date` 族的条件大致为：

- 有独立新闻列表页  
- 列表项能同时得到：链接 + 标题 + 日期（或紧邻）  
- 分页静态或可枚举  
- 详情 HTTP 可打开，正文可用通用抽取或轻模板拿到  

不满足的（门户/SPA/强反爬）排除本族主路径。

### 2) 每站 site_profile：槽位 + 多候选

布局差异落在 **槽位候选**，流水线相同：

| 槽位 | 含义 |
|------|------|
| list_item | 一条新闻容器 |
| item_link | 详情 URL |
| item_title | 列表标题 |
| item_date | 列表日期 |
| pager_next | 下一页 |
| detail_title / detail_date / detail_body | 详情补强 |
| url_path_allowlist | 如仅 `/about/news/\d+\.shtml` |

另存：`template_id`、`parse_version`、失败率、上次成功时间。

### 3) 冷启动 → 固化 → 热运行

1. **规则探针**：多套列表族解析器试跑，能稳定抽出足够条「url+title+date」则采用  
2. **失败才 LLM**：看一页 HTML，产出槽位 JSON（结构化、可校验）  
3. **小样本验收**（如 5 条）：日期可解析、正文长度合理 → 写入 profile  
4. **日常只跑规则**；抽检失败率升高 → 触发 profile 重建，而非全库停摆  

LangGraph 对应：`resolve_profile → crawl_with_profile → gate → maybe_repair_profile`。

## 稳定性保障清单

- 列表页优先采齐 url/title/date  
- 路径白名单降噪声  
- 质量门（日期格式、标题黑名单词、正文最小长度）  
- 模板版本可回滚  
- 同族共享编排，异布局只换 profile  

## 一句话

**同族能力相同，异布局靠每企 profile；LLM 用于冷启动/重修模板，不用于日频逐页自由爬。**
