### 3.2 Request / Response 模型

```python
# backend/app/api/schemas/news_url_crawl.py
"""新闻 URL Agent 抓取接口的请求与响应模型。"""
from __future__ import annotations

from typing import List, Optional

from pydantic import BaseModel, Field, HttpUrl


class NewsUrlCrawlRequest(BaseModel):
    """新闻 URL 抓取请求。"""

    news_list_url: HttpUrl = Field(..., description="新闻列表入口页 URL")
    known_urls: List[str] = Field(
        default_factory=list,
        max_length=500,
        description="上次已抓的详情页 URL；Agent 据此判断是否已翻到历史区域",
    )
    company_name: Optional[str] = Field(None, description="企业名称，辅助消歧")
    stock_code: Optional[str] = Field(None, description="证券代码，辅助消歧")
    max_pages: int = Field(8, ge=1, le=20, description="列表页抓取上限")
    trace_id: Optional[str] = Field(None, description="链路追踪 ID")


class NewsUrlItem(BaseModel):
    """单条新闻详情 URL。"""

    url: str
    title: str = ""
    published_at: Optional[str] = None


class NewsUrlCrawlStats(BaseModel):
    """执行统计。"""

    candidate_count: int = 0
    """Agent 在列表页上识别出的候选总数（含 known_urls）。"""

    known_hit_count: int = 0
    """命中 known_urls 的条数。"""

    list_page_urls: List[str] = Field(default_factory=list)
    agent_turns: Optional[int] = None
    agent_cost_usd: Optional[float] = None
    duration_ms: Optional[int] = None


class NewsUrlCrawlResponse(BaseModel):
    """新闻 URL 抓取响应。"""

    news_urls: List[NewsUrlItem] = Field(default_factory=list)
    """只含 known_urls 之外的新闻详情 URL。"""

    list_pages_fetched: int = 0
    stop_reason: str = "no_next"
    stats: NewsUrlCrawlStats = Field(default_factory=NewsUrlCrawlStats)
    trace_id: Optional[str] = None
```

**`known_urls` 上限 500**：一次抓取最多返回量级（实验最大 174）。给 500 足够宽松，同时防滥用。

### 3.3 路由实现

```python
# backend/app/api/routes/news_url_crawl.py
"""
新闻 URL Agent 抓取路由。

对接 exhibition：POST /api/v1/huayuan/news-url-crawl
同步执行：跑一次 Claude Agent，返回 known_urls 之外的新闻 URL。
无状态、无数据库依赖。
"""
from __future__ import annotations

import asyncio
import logging
import secrets

from fastapi import APIRouter, HTTPException

from backend.app.api.schemas.news_url_crawl import (
    NewsUrlCrawlRequest,
    NewsUrlCrawlResponse,
)
from backend.app.config import settings
from backend.domain.news_crawl.agent_runner import run_news_crawl_agent
from backend.domain.news_crawl.exceptions import (
    AgentExecutionError, AgentTimeoutError, ListFetchError,
)

logger = logging.getLogger(__name__)
router = APIRouter(tags=["新闻URL抓取"])


@router.post("/huayuan/news-url-crawl", response_model=NewsUrlCrawlResponse)
async def news_url_crawl(data: NewsUrlCrawlRequest) -> NewsUrlCrawlResponse:
    """
    跑一次 Agent，从新闻列表入口页发现新闻详情 URL。

    同步接口：Agent 实测耗时 2~4 分钟，调用方需给足超时（建议 ≥620s）。
    返回的 news_urls 已减去调用方传入的 known_urls。
    """
    if not settings.is_news_crawl_enabled:
        raise HTTPException(status_code=503, detail="新闻 URL 抓取未启用或未配置 Anthropic 凭证")

    trace_id = data.trace_id or secrets.token_hex(16)
    seed_url = str(data.news_list_url)
    logger.info(
        "[news-url-crawl] start trace_id=%s seed=%s known=%d max_pages=%d",
        trace_id, seed_url, len(data.known_urls), data.max_pages,
    )

    try:
        result = await asyncio.wait_for(
            run_news_crawl_agent(
                seed_url=seed_url,
                known_urls=data.known_urls,
                company_name=data.company_name or "",
                stock_code=data.stock_code or "",
                max_pages=data.max_pages,
                trace_id=trace_id,
            ),
            timeout=settings.NEWS_CRAWL_TIMEOUT_SECONDS,
        )
    except asyncio.TimeoutError:
        logger.error("[news-url-crawl] timeout trace_id=%s", trace_id)
        raise HTTPException(
            status_code=504,
            detail=f"Agent 执行超时（>{settings.NEWS_CRAWL_TIMEOUT_SECONDS}s）",
        )
    except ListFetchError as exc:
        # 列表页全部抓取失败 —— 通道或网络问题
        logger.error("[news-url-crawl] list fetch failed trace_id=%s: %s", trace_id, exc)
        raise HTTPException(status_code=502, detail=f"列表页抓取失败：{exc}")
    except AgentExecutionError as exc:
        logger.error("[news-url-crawl] agent error trace_id=%s: %s", trace_id, exc)
        raise HTTPException(status_code=502, detail=f"Agent 执行失败：{exc}")

    logger.info(
        "[news-url-crawl] done trace_id=%s pages=%d new=%d stop=%s cost=%s",
        trace_id, result["list_pages_fetched"], len(result["news_urls"]),
        result["stop_reason"], result["stats"].get("agent_cost_usd"),
    )
    return NewsUrlCrawlResponse(
        news_urls=result["news_urls"],
        list_pages_fetched=result["list_pages_fetched"],
        stop_reason=result["stop_reason"],
        stats=result["stats"],
        trace_id=trace_id,
    )
```

**超时保护是必须的**：实验里靠 `max_turns=50` 隐式兜底，生产必须有墙钟超时，否则一个僵死站点会永久占用 worker。

### 4.1 与实验代码的差异清单

| # | 实验实现 | 生产改造 | 原因 |
|---|---|---|---|
| 1 | `BASE_DIR` 模块常量 | 配置注入 | 服务化后不能依赖 CWD |

| 3 | `httpx.Client` 同步 | `httpx.AsyncClient` | 不阻塞事件循环 |

| 5 | 无 `known_urls` | **新增提示词 + 结果过滤** | 需求核心机制 |
| 6 | 无 `stop_reason` | **新增** | 可观测性；区分通道问题 |
| 7 | `MAX_PAGES=8` 常量 | 请求级 `max_pages` | 不同站点需求不同 |
| 8 | 快照落盘 | 默认关闭（可开关） | 生产不写盘 |
| 9 | 墙钟超时缺失 | 路由层 `asyncio.wait_for` | 防僵死 |

### 4.2 工具契约（保持实验验证有效的形状）

**不要改的四条**（这是实验证明有效的设计）：

1. **工具只回「简化后的同域链接清单」，不预分类** —— 不告诉 Agent 哪条是新闻、哪条是翻页。预分类会让 Agent 退化成规则执行者，失去泛化能力。
2. **返回值带 `pages_remaining` / `hint`，用工具契约引导循环**，不靠模型自觉。
3. **超限时工具拒绝执行并给出下一步指令。**
4. **反幻觉**：`record_news_urls` 只接受当次 `fetch_list_page` 返回过的候选 URL（v1 新增，建议保留）。

四个工具：

```python
@tool(
    "fetch_list_page",
    "抓取一个列表页，返回按页面顺序排列的同域链接清单。"
    "不预判哪条是新闻、哪条是翻页。禁止打开新闻详情。",
    {"url": str},
)
async def fetch_list_page(args): ...

@tool(
    "record_news_urls",
    "把当前列表页识别出的新闻入口 URL 写入内存库。"
    "items_json 为 JSON 数组，元素含 url，可选 title/published_at；"
    "next_page_url 为后续列表页绝对 URL，没有则传空字符串。不要打开详情页。",
    {"page_url": str, "items_json": str, "next_page_url": str},
)
async def record_news_urls(args): ...

@tool("get_state", "查看当前进度：已抓几个列表页、各页记录了多少新闻 URL。", {})
async def get_state(args): ...

@tool("save_results", "把新闻 URL 清单提交为最终结果。完成采集后必须调用。", {})
async def save_results(args): ...
```

### 4.3 `known_urls` 的两层实现

**L1 — 提示词注入**（见 §4.4），Agent 自行判断是否已翻到历史区域。

**L1 的可观测加成**：`record_news_urls` 返回值里带命中数，让 Agent 有明确信号可依，同时供统计：

```python
async def record_news_urls(args):
    ...
    hit = len({i.url for i in batch} & known_norm_set)
    return _text_result({
        "ok": True,
        "added": added,
        "total_news_urls": len(store.news_items),
        "known_hit_count": hit,                    # 新增
        "list_pages_fetched": len(store.list_pages),
        "pages_remaining": _pages_remaining(),
        "hint": _build_hint(hit),
    })


def _build_hint(hit: int) -> str:
    """按命中情况给出下一步指令。"""
    if hit > 0:
        return (
            f"本页有 {hit} 条命中调用方提供的已知新闻 URL，"
            "说明已翻到历史区域。除非本页仍有大量未记录的新 URL，"
            "否则应停止翻页并调用 save_results。"
        )
    return (
        "尚未达到最大页数时，请根据当前页内容自行寻找后续列表页并继续 "
        "fetch_list_page；达到上限或找不到后续列表页则 save_results。"
    )
```

> **为什么是「提示」而不是「硬停」**：同一页可能既含历史条目又含新条目（实验里首页就混着滚动推荐）。硬停会丢新 URL。

**L2 — 结果层过滤**（在 `save_results` / 返回前）：

```python
def filter_known(store: CrawlStore, known_norm: set[str]) -> list[NewsUrlItem]:
    """返回前减去 known_urls —— 兜底，保证返回值干净。"""
    return [
        NewsUrlItem(url=i.url, title=i.title, published_at=i.published_at)
        for i in store.news_items
        if url_norm(i.url) not in known_norm
    ]
```

### 4.4 系统提示词（移植 + 增补 `known_urls` 段）

沿用实验的约束（已验证有效），**增补**已知 URL 段落：

```text
你是企业新闻列表页的入口发现助手。任务：从给定的新闻列表入口页出发，
找出该企业新闻的详情页 URL 清单。

硬性约束：
1. 只能用 mcp__crawl__* 工具。禁止 Bash / WebFetch / WebSearch / Read / Write / Edit。
2. 不要打开新闻详情页 —— 本任务只要列表上的入口 URL，不要正文。
3. 不要把导航、栏目、公告栏、许可证公示、分页控件本身当成新闻入口。
4. 禁止依赖事先给定的翻页 URL、文件名或锚文本模式；
   后续列表页只能从当前页内容里发现。
5. 必须持续找后续列表页，直到没有后续或达到 max_pages 上限。
   不要只停在入口页。

判断提示：
- 同一站点里，列表页 URL 与详情页 URL 可能长得很像，
  要靠页面上呈现的内容来判断，不要只看路径。
- 若某页内容与之前页面高度重复，说明已到末页或服务端不支持翻页，
  此时应记录「无新增」并停止，不要编造 URL。

已知 URL 提示（重要）：
- 调用方会给出上一次已抓取的新闻详情 URL 清单（known_urls）。
- 若当前页大量出现这些 URL，说明已经翻到历史区域，
  应停止翻页并立即 save_results。
- 但仍需把当前页上「不在 known_urls 里的」新 URL 全部记录完再停。
```

**保留**「不要编造 URL」—— 实验里 600486 的 Agent 做到了「正确识别重复、正确停止、零幻觉」，提示词是其原因之一。

### 4.6 阻塞点处理（必须解决）

实验的 `crawl_runtime.fetch_html` 是**同步 `httpx.Client`**。三种处理方式：

| 方案 | 做法 | 评价 |
|---|---|---|
| **A（推荐）** | 改 `httpx.AsyncClient`，MCP 工具本就是 `async def` | 最干净，工具签名不变 |
| B | `await asyncio.to_thread(fetch_html, url)` | 改动最小，但每页起线程 |
| C | 给 Agent 单独开线程跑整个 SDK 会话 | 隔离好但复杂 |

选 **A**。

> ⚠️ 另一处阻塞：`ClaudeSDKClient` 通过子进程与 CLI 通信。整段 `async with ClaudeSDKClient(...)` 必须在该请求协程内 `await`，**不要包在 `to_thread` 里**（会与事件循环冲突）。

### 4.8 `stop_reason` 判定

```python
def decide_stop_reason(store, hit_known: bool, max_pages: int) -> str:
    """判定停止原因。顺序重要：通道问题优先于正常的末页。"""
    if not store.news_items and store.list_pages:
        return "no_detail_links"        # 抓到页面但抽不到详情链 → 通道问题
    if hit_known:
        return "hit_known"
    if len(store.list_pages) >= max_pages:
        return "max_pages"
    return "no_next"
```

**判断顺序是关键**：先把 `no_detail_links` 挑出来，否则「抓到页面但零链接」的通道故障会被误报成 `no_next`（看起来像正常到末页）。

```python
        600, description="单次抓取墙钟超时（秒），超时返回 504"
    )
    NEWS_CRAWL_REQUEST_INTERVAL: float = Field(
        0.4, description="同站抓取最小请求间隔（秒），礼貌爬取"
    )
    NEWS_CRAWL_SAVE_SNAPSHOT: bool = Field(
        False, description="是否保存 HTML 快照（仅调试期开启）"
    )

    @property
    def is_news_crawl_enabled(self) -> bool:
        """新闻抓取可用性：显式开启 + 有凭证。"""
        has_credential = bool(self.ANTHROPIC_AUTH_TOKEN or self.ANTHROPIC_API_KEY)
        return bool(self.NEWS_CRAWL_ENABLED and has_credential)
```

**注意**：v1 的 `is_news_crawl_enabled` 还要求 `is_database_enabled` —— v2 **去掉**，因为本功能不碰数据库。

## 6. 部署

### 6.1 镜像改造（唯一的高不确定性项）

**当前 `Dockerfile` 构建不出可运行本功能的镜像**，缺两样：

| 缺什么 | 为什么需要 | 怎么补 |
|---|---|---|
| **Node.js + `claude` CLI** | Claude Agent SDK 是 **CLI 子进程模型**，必须本机有 `claude` 可执行文件（实验用 2.1.270） | 镜像内装 Node 20+ 并全局装 CLI |
| **`claude-agent-sdk`** | 未在任何 `requirements*.txt` 中 | 加入 `requirements-huayuan.txt` |

Dockerfile 增量（示意）：

```dockerfile
# Node.js 运行 claude CLI（Agent SDK 的运行时依赖）
RUN apt-get update \
    && apt-get install -y --no-install-recommends ca-certificates curl gnupg \
    && curl -fsSL https://deb.nodesource.com/setup_20.x | bash - \
    && apt-get install -y --no-install-recommends nodejs \
    && npm install -g @anthropic-ai/claude-code \
    && rm -rf /var/lib/apt/lists/*

# 注意：CLI 需要可写 HOME（会写 ~/.claude 配置与缓存）
ENV HOME=/app
```

**验证方式**：容器内 `claude --version` 必须成功，否则 Agent 会在运行时才报错。

> ✅ **v2 好消息**：因为不再需要数据库，`ENABLE_DATABASE=false` **无需改动**，v1 的第二个部署阻塞项自动解除。

### 6.2 超时配置

| 侧 | 项 | 值 |
|---|---|---|
| gd25 | `NEWS_CRAWL_TIMEOUT_SECONDS` | **600** |
| gd25 | `max_turns` | 50 |
| exhibition | 客户端读超时 | **≥620s** |

⚠️ **若前置 Nginx / 网关，必须同步调大其 `proxy_read_timeout`**，否则会被网关先切断（默认常为 60s）。这是最容易漏的一环。

### 6.3 并发与资源

本接口是**长同步请求**。FastAPI 默认无并发限制 —— 若有多个调用方同时触发，会同时跑多个 Agent。

| 项 | 建议 | 说明 |
|---|---|---|
| 并发上限 | **1~2** | 每次 $0.73 且跑 2~4 分钟 |
| 实现方式 | `asyncio.Semaphore(settings.NEWS_CRAWL_MAX_CONCURRENCY)` | 超出的请求**排队等待**（不拒绝） |
| 内存 | +512MB | SDK 子进程 |

```python
# 模块级信号量，限制同时运行的 Agent 数
_semaphore = asyncio.Semaphore(settings.NEWS_CRAWL_MAX_CONCURRENCY)

async def _run_with_semaphore(**kwargs):
    async with _semaphore:
        return await run_news_crawl_agent(**kwargs)
```

> **排队 vs 拒绝**：排队更友好（调用方本就在等），但会让请求总耗时超过 600s。建议：**排队 + 现有 600s 超时** —— 排队过久的请求自然超时返回 504，调用方重试即可。

## 8. 错误处理

| 异常 | HTTP | 处理 |
|---|---|---|
| `news_list_url` 非法 / `max_pages` 越界 / `known_urls` 超限 | 422 | Pydantic 自动 |
| Agent 超时（>600s，含排队） | 504 | `asyncio.wait_for` 取消 |
| 列表页全部抓取失败 | 502 | `ListFetchError` |
| Agent `is_error=true` / SDK 异常 / CLI 不可用 | 502 | `AgentExecutionError` |
| 未启用或未配凭证 | 503 | `is_news_crawl_enabled=false` |
| 站点为 JS 渲染 | **200** | `stop_reason=no_detail_links`（不是错误，是信号） |

**`no_detail_links` 返回 200 而非错误码**：这是「成功执行但结果为零」，与「执行失败」语义不同。调用方据 `stop_reason` 决定是否告警。

| 层 | 用例 |
