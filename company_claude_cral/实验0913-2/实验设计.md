# 实验0913-2：Agent 能否稳定"从入口发现新闻 URL"（含翻页）

> 依据：`我的思路.md`
> 目标：验证 Claude Agent SDK 在**多站**上抽取新闻列表 URL 的稳定性
> 时间：2026-09-13

---

## 一、实验命题（可证伪）

> **给定一个公司官网新闻入口页，Agent 能自主发现该站的翻页规律，并至少翻 3 页、把各页的新闻详情 URL 抽全。**

**为什么选这个命题：** 这是 `讨论0913-1/结论.md` §2.1 划出的 Agent **能力区（定界类）** 中最核心、且唯一有对照组的一项。详情抽取（抽取类）单独留待后续实验，不混在本实验里。

**本实验只做"发现新闻 URL"，不打开详情页、不抽正文。** 理由：
- 减少变量 —— 抽取质量会污染对"发现能力"的判断（`结论.md` §2.2 的教训）
- 降低成本与耗时
- 详情抽取已被判定"实测未改善"，另行设计

## 二、设计（严格按 `我的思路.md`）

| 要求（原话） | 本实验落实 |
|--------------|-----------|
| "设计5个网站" | **6 个站**（比要求多 1，因为要覆盖不同翻页形态；见 §3） |
| "让Agent分5次（每个网站一次独立的Agent发起）" | **每站一个独立进程 + 独立 ClaudeSDKClient 实例**，站间无共享状态、无上下文传递 |
| "测试Claude Agent SDK的网站获取的能力是否稳定" | 每站跑 **3 次**，记录成功率方差（单次无稳定性可言，见 `结论.md` §3.3） |
| "必须翻页拿内容，否则不算成功。至少翻页3次" | 通过条件 = **发现并成功跟进 ≥3 个列表页**（即入口页 + ≥2 后续页，共 ≥3 页），且后续页**必须贡献入口页没有的新 URL** |

### 2.1 关于"至少翻页3次"的口径

严格按字面：**抓取列表页数 ≥ 3**。但如果第 2、3 页拿到的 URL 与第 1 页完全重复，那是"翻了个假页"。

**因此双重判定：**
1. `list_pages_fetched >= 3`（页数达标）
2. `later_page_unique_urls >= 5`（后续页确实贡献了新 URL —— 防"翻页假成功"）

**两条都满足才叫通过。** 单看页数会被"重复请求同一页"骗过。

### 2.2 独立站 vs 共享站

`我的思路.md` 说"每个网站一次独立的Agent发起"。本实验采用**更严格的独立**：

- 每站一个 **独立 Python 进程**（不是同一进程内循环）
- 每站一个**新的** `CrawlStore`（内存库不复用）
- 站与站之间**不传递任何提示或经验**

→ 这才能回答"换一个新站，它还稳不稳"。

## 三、6 个站的选择（覆盖不同翻页形态）

全部来自 `company_news_crawl/实验/实验260913-2-翻页验证/输入/seed_pagination.json`，**带有规则版的对照数据**。

| # | 代码 | 公司 | 翻页形态（已探测） | 规则版表现 | 难度 |
|---|------|------|-------------------|-----------|------|
| 1 | 000001 | 平安银行 | `index_2.shtml` ~ `index_N.shtml` | 命中 0/25（翻页失败） | 易（样板站） |
| 2 | 600486 | 扬农化工 | 锚文本"下一页" → `...Gone2.html` | 无增量 | 中 |
| 3 | 920139 | 华岭股份 | `?2.html` `?3.html` + `index.php?...page=N` | 有增量（关键词蒙中） | **难**（列表页与详情页路径极像，见下） |
| 4 | 000955 | 欣龙控股 | `?catid=93&page=N` | 无增量 | 中 |
| 5 | 300582 | 英飞特 | 锚文本"下一页" → `news_company/2.html` | **零产出** | **难**（规则版完全失败） |
| 6 | 920478 | 峆一药业 | `?&p=N`（共 6 页） | 无增量 | 中 |

**华岭的额外价值：** 它的列表页是 `/news/class/?1.html`、`?2.html`，而详情页是 `/news/html/?101.html` —— **两者只差一个路径段（class vs html）**。这是对"Agent 能否区分列表页与详情页"的极佳压力测试。规则版在这里靠 `news` 关键词蒙对，Agent 必须靠语义判断。

**英飞特的额外价值：** 规则版**零产出**（0 篇）。如果 Agent 能在这站拿到 ≥3 页，是对"从 0 到 1"最有力的证明。

## 四、Agent 的输入与约束

### 4.1 给 Agent 的（与 `ClaudeTest02` 一致，已验证有效的形状）

- **工具只回"简化后的同域链接清单"**，每条含 `href / text / title / nearby / date_in_text`
- **不预分类** —— 不告诉它哪条是新闻、哪条是翻页
- 工具返回值带 `pages_remaining` / `hint` 引导循环
- **禁止** Bash / WebFetch / Read / Write / Edit

### 4.2 明确**不给** Agent 的（防止作弊）

- ❌ 翻页 URL 规律（不给 `index_`、`page=`、`?p=` 等任何模式）
- ❌ 该站的详情页路径特征（不给 `/news/html/`、`/about/news/` 等）
- ❌ 规则版的抽取结果
- ❌ 裁判的真值（`verify_*.py` 里的 ground truth **只用于判分**）

### 4.3 提示词的关键约束（沿用实验里被证明有效的）

```
1. 只能用 mcp__crawl__* 工具
2. 禁止打开新闻详情页，禁止抽正文
3. 不要把导航、栏目、公告栏、许可证公示、分页控件本身当成新闻入口
4. 禁止依赖事先给定的翻页 URL、文件名或锚文本模式；后续列表页只能从当前页内容里发现
5. 最多抓 max_pages 个列表页。请一直找后续列表页，直到没有后续或达到上限。不要只停在入口页
```

**第 4 条是本实验的核心** —— 它把"翻页发现"变成必须靠 Agent 自身完成的动作。

## 五、判分（独立的裁判，与被测分离）

### 5.1 裁判怎么拿到真值

裁判**自己重新抓站**，用站点特定的规则算出真值（该规则**只写在裁判里，永不进提示词**）：

| 站 | 裁判真值规则 |
|----|-------------|
| 平安 | 详情路径 `/about/news/\d+\.shtml` |
| 扬农化工 | `/xwzx/hyzx/A158004001Gone\d+\.html` |
| 华岭 | 详情路径 `/news/html/?\d+\.html`（注意与列表页 `/news/class/` 区分） |
| 欣龙控股 | 详情路径含 `/news_detail` 或 `news.php?catid=93&id=` |
| 英飞特 | `/news_company/\d+\.html` 中排除列表页序号 |
| 峆一药业 | `/news/\d+` 或站内详情页特征 |

> ⚠️ 裁判规则需在实现时逐站确认（探测阶段已获得分页结构）。

### 5.2 判定指标

| 指标 | 含义 | 通过门槛 |
|------|------|----------|
| `list_pages_fetched` | 实际抓到的列表页数 | **≥ 3**（硬要求，来自 `我的思路.md`）|
| `later_page_unique_urls` | 后续页独有的详情 URL 数 | **≥ 5**（防"翻假页"）|
| `hit_rate` | 抽到的 URL ∩ 真值 / 抽到的 URL | ≥ 0.9（防噪声）|
| `recall` | 抽到的 URL ∩ 真值 / 真值 | 报告用（不做硬门槛，因为真值规则本身有误差）|
| `noise_count` | 抽到的非详情 URL（导航/公告/列表页自身） | ≤ 2 |
| `agent_turns` / `cost_usd` | 成本 | 报告用 |
| `errors` | 工具层错误数 | 报告用 |

**单站通过 = `list_pages_fetched >= 3` AND `later_page_unique_urls >= 5`。**

### 5.3 每站跑 3 次

| 站 | run1 | run2 | run3 | 站级判定 |
|----|------|------|------|----------|
| ... | ✅/❌ | ✅/❌ | ✅/❌ | **3/3 通过 = 稳定** |

**整体判定：**
- **PASS**：≥5/6 站达到 3/3
- **PARTIAL**：≥5/6 站达到 ≥2/3
- **FAIL**：否则

（"3/3"是"稳定性"这个命题的最低证据；2/3 说明方差大，需加强 profile 沉淀思路。）

## 六、要观察的现象（定性，同样重要）

1. **它怎样发现翻页的？** 读锚文本？读页码数字？猜 URL 模式？→ 看 `agent_trace`
2. **不同翻页形态，发现方式是否不同？** （`index_N` / `?page=N` / `?p=N` / "下一页"）
3. **它会不会把列表页当成详情页？**（华岭的 class vs html 是重点）
4. **它会不会漏掉后续页？**（只看 `pages_remaining` 就不翻了？）
5. **3 次运行之间的差异在哪？**（路径稳定性）
6. **失败时，是"没发现翻页"还是"发现了但没跟"？**

→ 这些观察决定了 `讨论0913-1/结论.md` §7 的三个待决策问题的答案（尤其"该不该沉淀 profile"）。

## 八、与 `ClaudeTest01/02` 的区别（本实验的增量）

| 维度 | ClaudeTest02 | 本实验 |
|------|--------------|--------|
| 站点数 | **1**（平安） | **6** |
| 每站运行次数 | **1** | **3** |
| 翻页要求 | 最多 5 页（软） | **≥3 页（硬性通过条件）** |
| 后续页有效性校验 | 有（`hit_later >= 5`） | 有（沿用并强化） |
| 独立进程 | 单站无所谓 | **每站独立进程**（严格隔离） |
| 裁判真值规则 | 硬编码平安 | **6 站各一套**（含易混路径的华岭） |
| 噪声计量 | 无 | 有（`noise_count`） |

**核心增量：把 n=1 变成 n=18（6 站 × 3 次），消除"过拟合到平安"这个最大偏差。**

## 九、已知风险与不做的事

| 风险 | 应对 |
|------|------|
| 6 站里仍有 1 站（平安）参与过原实验设计 | 平安只作"回归对照"，**判定看另外 5 站** |
| 裁判真值规则本身可能不准 | `recall` 不做硬门槛；导出 URL 清单供人工抽查 |
| 目标站改版/临时不可达 | 运行前先探活，不可达的站记 `unreachable` 并从分母剔除（并报告） |
| 第三方网关（`unidtai.com`）波动 | 记 `error` 与 turns；连续 2 次网关错误则标记环境问题而非 Agent 问题 |

**不做：**
- ❌ 不打开详情页、不抽正文（本次范围外）
- ❌ 不测 site_profile 沉淀（后续实验）
- ❌ 不用 Playwright（通道问题不在本次范围）
- ❌ 不调提示词去适配任何单站（一旦调了，n=6 的价值归零）
