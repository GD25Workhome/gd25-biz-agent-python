## 2. 运行架构

```text
Java (exhibition)
   |
   |  POST /api/v1/huayuan/radar-event-score
   v
FastAPI route  backend/app/api/routes/huayuan_radar_event.py
   |
   |  flow v3: radar_event_react_node
   |            -> radar_rule_gate (function)
   |            -> radar_event_audit_node (agent)
   |
   |  tools: deepseek_web_search / deepseek_fetch
   |         region_lookup / region_children
   v
华院 LLM 网关 (provider=huayuan)
DeepSeek Search / Fetch
   |
   v
响应解析：radar_event_scores[] + evidences + discarded + revision
   |
   +--> HTTP 直接返回 Java
   |
   +--> radar_score event worker（可选自动任务）
          认领 radar_event_job
          -> prepare 读 MySQL（企业 / 历史事件 / 时间窗）
          -> 进程内调用同一 route
          -> self_check -> event_update -> region_resolve -> radar_event_store
          -> 写 radar_event / radar_event_evidence / 收口 radar_event_job
```

运行期没有 Node、LLM CLI、向量库、PostgreSQL、Redis、Alembic（AnySearch 为可选工具，默认只注册、不参与 v3 flow）。

## 4. 关键数据流

### 4.1 HTTP 同步路径

```text
Java request
  -> route: trace_id / context / prompt_vars
  -> FlowManager.get_flow(huayuan_radar_event_agent_v3)
  -> react 节点：DeepSeek Search/Fetch + region 工具
  -> rule_gate：时效 / 日期 / 来源硬闸，产出 radar_audit_required
  -> auditor：只降不升的语义复核，产出最终 radar_event_scores[]
  -> route: edges_var 优先解析，回退 AI 文本
  -> HTTP 200: radar_event_score（primary）+ radar_event_scores[] + revision
```

### 4.2 Worker 自动路径

```text
scheduler._tick
  -> reclaim_stale（RUNNING 超时退回 PENDING）
  -> 未配 DEEPSEEK_SEARCH_KEY：暂停认领
  -> claim_jobs（status=0 -> RUNNING，FOR UPDATE SKIP LOCKED）
  -> execute.run_event_end_to_end
       prepare.fetch_job_and_company / load_history_events / build_request_body
       -> _score（进程内调 route）
       -> self_check.check（可能置 expired / 剔除证据）
       -> event_update.decide_action（INSERT 或 NOOP）
       -> region_resolve.resolve_event_region
       -> radar_event_store.insert_event / replace_evidences / touch_latest_event
       -> update_job_success / update_job_failed
```

失败分流：确定性错误（DataError / IntegrityError / ValueError 等）→ FAILED；网络 / 依赖抖动 → PENDING 重试，超过 `RADAR_SCORE_MAX_RETRY` 后 FAILED。

## 8. 关键坑摘要

- **多事件顶层共享证据**：模型可能把 `evidences[]` 放顶层；解析时必须注入到每个事件，否则 R2「有分必有据」误杀。
- **异常链重试分类**：路由把 `ValueError` 包成 `HTTPException` 后，`is_retryable` 必须沿 `__cause__` / `__context__` 看内层，否则确定性错误会无限重跑。
- **列宽截断**：Python 直写前必须按 `_EVENT_MAX` / `_EVIDENCE_MAX` 截断，否则 MySQL 1406 整单回滚。
- **region_source 长度**：`COMPANY_INHERITED` 17 字符，列宽必须 ≥ 32/64；当前 DDL 已加宽。
- **auditor 只降不升**：复核节点只能降级 / 置 expired，不能把硬闸结果改好。
- **Docker `--env-file` 引号**：`HUAYUAN_API_KEY="sk-..."` 会把双引号带进容器导致 401；K8s Secret 不受影响。
- **只插不更不关**：不要再恢复 `update_event` 的调用；它会覆盖 `published` / `verify_status`。
