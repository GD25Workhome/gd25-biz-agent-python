不是 AnySearch 工具本身的问题。工具是一样的，差异在于**怎么用**它。

### 核心差异：搜索词决定结果质量

AnySearch 本质上是一个网页搜索引擎，它的召回能力取决于你喂给它的 query。你的 Agent 和我使用同一个工具，但搜索策略不同，结果自然不同。

打个比方：同样是搜索引擎，搜 `"北投科技" 展厅` 和搜 `"北投科技" 展厅 招标 采购 改造` 返回的结果质量天差地别。后者把太多意图塞进一条 query，搜索引擎会把它当词袋处理，噪声极高——这正是你自己提示词里也明确禁止的做法，说明你是清楚这个约束的。

### 你的 Agent 搜索策略的问题

你的提示词里写了"一次查询只表达一个意图"，这个原则是对的。但你的"固定搜法"过于保守：

- **第 1 步**只搜 `"公司名" 展厅`
- **第 2 步**才搜 `"公司名" 展厅 招标`

问题在于：如果第 1 步没命中，第 2 步加了"招标"反而更窄了。而且你完全没有覆盖"展厅"的同义词——**企业馆、体验中心、文化中心、展陈、科普基地**这些词在招投标公告里出现的频率并不低。

### 具体改进建议

**1. 第一轮搜索就做语义扩展（并行而非串行）**

不要只搜一个 query，第一轮同时发 2~3 条：

```
"北投科技" 展厅
"北投科技" 体验中心
"北投科技" 展陈
```

这三条各自意图单一、不堆砌，符合你"一次一个意图"的原则，但覆盖面翻倍。

**2. 第二轮针对"动作"搜索，而非加宽"对象"**

```
"北投科技" 展厅 招标
"北投科技" 展厅 采购
```

如果第一轮已经找到了"空间存在"的线索但没找到"项目动作"，第二轮聚焦找动作。

**3. 对 AnySearch 返回结果的二次过滤要更严格**

你提到 Agent 抓到了 `Example Domain` 这种无效页面——这不是工具的问题，而是你的 Agent 没有对返回的 URL 做**可达性预判**。建议在 `anysearch_extract` 之前加一步：如果 URL 的域名是已知的低质量源（如聚合站、镜像站），直接跳过，换同标题的其他来源链接。

**4. 利用 extract 做深度验证而非广度搜索**

你的 Agent 把 extract 用得太省了。正确用法是：搜索负责"广撒网"，extract 负责"深验证"。当搜索摘要里出现模糊线索（比如标题提到"北投科技展厅"但摘要没写清是新建还是参观），就应该 extract 进去看正文，而不是直接丢弃。

### 总结

| 维度 | 你的 Agent | 改进方向 |
|------|-----------|---------|
| 搜索词覆盖 | 只搜"展厅" | 并行搜"展厅/体验中心/展陈" |
| 搜索轮次 | 线性递进 | 第一轮广撒网，第二轮聚焦动作 |
| 结果过滤 | 依赖摘要判断 | 对模糊线索用 extract 深验证 |
| 坏链接处理 | 无 | 增加无效页面识别和换源逻辑 |

**工具没问题，prompt 里的搜索策略需要升级。** 把"固定搜法"从单线改成"扇形展开 + 纵深验证"，效果会有明显提升。
