## 1. 实验做了什么（客观复述）

两个迭代，共用同一套确定性运行时 `crawl_runtime.py`：

| | ClaudeTest01 | ClaudeTest02（更晚、更精炼） |
|---|---|---|
| 范围 | 列表页 + 打开详情 + 抽正文 + mock 增量去重 | **只抽列表页 URL**，明确禁止打开详情 |
| 列表页上限 | 2 | 5 |
| MCP 工具 | 6 个（`fetch_list_page` / `record_news_items` / `load_history` / `extract_articles` / `get_state` / `save_results`） | 4 个（去掉 history/articles） |
| 权限 | `allowed_tools` 白名单 + `disallowed_tools` + `bypassPermissions` | 同 |
| 结果 | `passed: true`，9 turns，**$0.4767** | `passed: true`，12 turns，**$0.823** |

**核心设计（这才是实验的真正价值）：**

```
Agent 只用 mcp__crawl__* 工具
  禁止 Bash / WebFetch / WebSearch / Read / Write / Edit
  ↓
fetch_list_page(url) → 返回「简化后的同域链接清单」，【不预分类】
  每条：href / text / title / nearby / date_in_text
  ↓
Agent 自行判断：哪些是新闻入口？哪条是下一页？
  ↓
record_news_urls(page_url, items_json, next_page_url) → 写入内存库
  ↓
save_results() → Markdown + JSON
```

**"不预分类"是关键**。`simplify_list_html()` 只做确定性清洗（剔 script/style、同域过滤、去重、URL 归一化、抽 `date_in_text`），把语义判断完全留给模型。`extract_pingan_news_urls()`（正则 `/about/news/\d+\.shtml$`）虽然存在于同一文件，但**只作为裁判，不提供给 Agent** —— 这个"裁判与被测分离"的做法是实验里最值得保留的工程习惯。

## 2. 成立的部分（强证据）

### 2.1 翻页发现：Agent 能自己找到翻页规律

ClaudeTest02 的 trace 显示 Agent **在未被提示任何 URL 模式的前提下**，连续发现并跟随：

```
page 1: http://bank.pingan.com/bankPingAnCom/about/news
page 2: http://bank.pingan.com/about/news/index_2.shtml
page 3: http://bank.pingan.com/about/news/index_3.shtml
page 4: http://bank.pingan.com/about/news/index_4.shtml
page 5: http://bank.pingan.com/about/news/index_5.shtml
```

注意 page 1 与 page 2 的**路径不同**（`/bankPingAnCom/about/news` vs `/about/news/`），跳转后 `final_url` 变了。Agent 是从页面内容里读出 `index_2.shtml` 的，不是猜的 —— 提示词里明确写了"禁止依赖事先给定的翻页 URL、文件名或锚文本模式"。

**成绩：**

| 指标 | 值 |
|------|---|
| 列表页数 | 5 |
| 新闻 URL 总数 | **125**（25/页，均匀） |
| 首页命中 | **25/25** |
| 第 2~5 页独有 URL 命中 | **99/99** |
| 错误数 | 0 |

对比规则版（`实验260913-2`）：平安 B 组相对 A 组新增 **0**，`index_2.shtml` 命中 **0/25**。

→ **从 0/25 到 99/99。这是本次实验最硬的一条结论，且是唯一一条有对照组（规则版）的结论。**

### 2.2 噪声辨识：Agent 确实在"辨识"而非"发现"

`news_urls.md` 里 125 条 URL 全部落在 `/about/news/\d+\.shtml`，**没有一条 `/gonggao/` 公告、没有一条导航页**。而规则版在平安上把 `/about/gonggao/` 吸进了约 10 条。

→ Agent 在 P3（噪声定界）上有效，且这个能力是**提示词级别的**（"不要把导航、栏目、公告栏、许可证公示、分页控件本身当成新闻入口"），不需要额外工程。

### 2.3 工具返回值引导循环：可控

`fetch_list_page` 在超出上限时**拒绝执行**并回 `请调用 save_results`；`record_news_urls` 在还有余量时回 `hint` 提示继续。Agent 12 turns 内全程没有越界、没有乱调工具、最后自觉 `save_results()`。

→ **不依赖"模型自觉"**，靠工具契约约束行为，这是可以工程化的。

### 2.4 裁判与被测分离

`verify_pagination()` 自己重新抓真值（`index_2..index_5.shtml` **只写死在裁判里，从不进提示词**），再比对 Agent 产出，`main()` 返回 0/1 决定 CI 成败。

→ 这个结构应该被保留到后续所有验证里。

## 3. 不成立 / 未证明的部分（必须显式记录）

### 3.1 n = 1：只跑过一个站

两个实验都是**平安银行单站、单 URL、单公司**。而规则版的对照组 `实验260913-2` 是 **6 个站**。

→ **25/25 与 99/99 不能外推到"这套方案对 2904 站有效"**。平安恰好是既有分析判定的"规则友好型样板站、普通偏易"。在**最难**的站（大悦城门户、神州数码卡片）上一个都没测过。而恰恰是这些站，才是引入 Agent 的正当理由。

### 3.2 详情抽取没有改善（实测）

见 `01` §3。`ClaudeTest01` 的抽取器是**规则**，`published_at 20/20` 是**列表字段兜底**的结果，正文仍混入详情页 `h5` 日期与公示噪声。

→ **"Agent 让内容抓取更稳定"这句话，在详情内容这一半上，目前的证据是反的（没变好）。**

### 3.3 单次运行，没有稳定性数据

每个实验各跑一次。而"稳定性"是个**分布**概念。9~12 turns、$0.48~0.82 都是单点采样，没有方差、没有失败率。

→ 不知道它会不会 10 次里错 3 次 —— 而这正是要解决的问题本身。

### 3.4 裁判口径偏窄

`passed` 的判定是：`list_pages >= 2 and hit_later >= 5 and hit_page1 >= 5`。

- **不检查标题/日期质量**（所以详情抽取的脏数据溜过去了）
- **不检查漏抽**（只算命中，不算 recall 分母是否完整覆盖真值；`pending` 的 URL 没被追究）
- 阈值（5）相对真值（25）很低，宽容度大

→ 这条判据能证明"没完全失败"，不能证明"达到生产质量"。

### 3.5 是"乐观证据"而非"中立证据"

实验的组织方式是：**先在平安这个已知样板站上定义简化器与提示词，再在同一个站上验证**。`simplify_list_html()` 里甚至保留了平安专属的 `otitle` 属性读取。

→ 有**过拟合到测试样本**的风险。同样的方法论换到未参与设计的站上，结果可能差很多。**这是最需要在下一轮消除的偏差。**

## 5. 归因修正：Agent 的价值到底是什么

实验文字容易给人"Agent 比规则强得多"的印象。**正确归因是：**

**Agent 拿到的输入已经被规则处理过了。** `simplify_list_html` 做了：剔脚本 → 同域过滤 → 去重 → URL 归一化 → 逐条附带 `href/text/title/nearby/date_in_text`。

所以：

| 环节 | 谁干的 |
|------|--------|
| 找到链接、洗干净、归一化 | **规则** |
| 认出哪条是新闻、哪条是翻页 | **Agent** |
| 抓 HTML、抽正文 | **规则** |

→ 结论：**Agent 的增量是"辨识/定界"，不是"发现/抓取"。** 它不提高抓取能力上限，提高的是**规则未命中先验时的判断力上限**。

**由此推出本文最重要的经济论点：**

> Agent 单站 $0.48~0.82，相对纯规则（**成本 0**）是**净增支出**。它不可能靠"省 token"自证价值。
> **它唯一的正当性来自"省人"** —— 省掉①人工为每个新站写选择器 ②站点改版后人工修规则 ③人工判"这站到底能不能规则爬"。
>
> 因此：**逐次付 LLM 钱的用法（日频篇篇开）不成立；一次性付钱后沉淀为规则/配置的用法（冷启动 + 改版重建）才成立。**

这条论证不依赖 n=1 是否可外推 —— 即使 Agent 在 2904 站上行得通，成本结构也要求它必须是**低频**的。
