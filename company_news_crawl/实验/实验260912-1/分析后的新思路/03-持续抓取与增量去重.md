# 持续抓取与增量去重

场景：隔几天或每周对同一批官网新闻源再抓。业务方可提供 **历史已抓网页 URL** 与 **最近公告日期**——作为标准增量入参很合适。

## 增量任务契约（建议）

```text
stock_code
list_url
seen_urls[]          # 历史已抓详情 URL（或等价：可查库 + 最近窗口）
watermark_date       # 该源已覆盖到的最新发布日
last_success_at      # 可选
site_profile_id      # 可选，已绑定模板
```

## 过滤与早停（推荐优先级）

```
翻列表（从第 1 页起）
  → 解析 items[{url, title, date}]
  → 过滤：
       A. url ∈ seen_urls                 → 跳过（主去重）
       B. date < watermark_date           → 可跳过/少抓（水位）
       C. date == watermark 但 url 未见   → 仍抓（同日多篇）
  → 连续整页皆「旧」→ 停止继续翻页
  → 抓详情 → 入库前再查 url_norm / content_hash
  → 回写：新 URL 并入 seen；watermark = max(旧水位, 本批最大 date)
```

## 三种去重手段

| 手段 | 角色 | 注意 |
|------|------|------|
| url_norm 唯一 | **主去重** | 统一协议、去尾斜杠、去跟踪参数 |
| watermark_date | **控翻页范围** | 解析失败时不能唯一下刀；同日多篇靠 URL |
| content_hash | **辅去重** | 防换链同文；正文抽脏时 hash 可能漂 |

## LangGraph 节点映射

- `load_incremental_cursor`：读 seen_urls + watermark  
- `paginate_until_stale`：带早停翻页  
- `filter_new_items`：URL ∪ 日期过滤  
- `dedupe_write`：入库前查重  
- `update_cursor`：回写水位与新 URL（或业务回调）

## 运维建议

- 日常：严格增量 + 早停  
- 定期（月/季）：允许深翻或水位前多翻几页，防止漏页与改版  
- 游标与正文库分离：即使业务暂时只给「最近日期 + 部分 URL」，库内仍应以 url_norm 为准做最终去重  

## 一句话

**业务给历史 URL + 最近公告日当游标；流程内 URL 去重为主、日期水位为辅、hash 兜底；抓完抬高水位。**
