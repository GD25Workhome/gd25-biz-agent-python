## 2. 按测试点记录

### 2.1 平安银行 `.../about/news`：第一页是否抓全？能翻页吗？

- **第一页新闻条目**：列表 HTML 中可定位的 `/about/news/{id}.shtml` 共 **25** 条（锚文本含日期+标题，质量好）。
- **覆盖率**：这 25 条 URL 在本次输出中 **命中 25/25（100%）**，第一页新闻链已全部进入抓取集合并成功落正文。
- **为何文章数是 49 不是 25**：抽链启发式较宽，同页还吸入了公告 `/about/gonggao/`（约 10）、其它导航类链接等；`--max-articles 50` 截断前共抽到 103 条候选。
- **翻页**：页面存在明确分页链接 `index_2.shtml` … `index_26.shtml`，以及「下一页/尾页」文案。  
  **当前脚本不会跟随分页**，只吃入口列表页。历史新闻若在第 2 页及以后，本次实验**抓不到**。
- **质量问题**：正文大多能抽到（`/about/news/` 下约 35 篇正文长度尚可），但 **title 字段大量落成「组织架构」**（站点公共导航/页眉被当成标题），不能直接给 Agent 当标题用；应以列表锚文本或正文内标题回填。

### 2.2 大悦城 `.../about/news`：门户页难抓，效果如何？

- 入口页更像 **集团门户/聚合页**（标题「大悦城-大悦城控股官网」），不是干净的「新闻列表 + 分页」。
- 同页混有大量 `/detail/*.html`、`/hotel/*` 等链接；本次落库 36 篇中：约 **15** 条 detail、**4** 条 hotel、其余 17 条为其它同域链接。
- 抓取过程错误较多（该公司 error_count=14），稳定性一般。
- **标题几乎全部错误**（33/36 为「中粮集团成员企业」），正文中位长度约 349 字，偏短，疑似抽到公共模块而非新闻正文。
- **结论**：MVP 对「门户型入口」能「抓到一些 detail 页」，但 **噪声高、字段脏**，不适合直接进知识库。需要：① 找到真正新闻列表子频道 URL；② 收紧同域路径白名单（如仅 `/detail/` 且排除 hotel）；③ 改进标题/正文抽取选择器。

### 2.3 神州数码 `.../aboutus/news.html`：卡片式风格

- 本次 HTTP **200**（此前探测曾出现 521，说明该站偶发不稳定）。
- 页面带「下一页」等分页文案，但 HTML 里几乎看不到静态 `index_N` 链，**分页偏前端/脚本**，当前 MVP **不能翻页**。
- 列表区真实资讯详情链很少：`aboutus/news/details*.html` 仅约 **4** 条；同时页脚/产品区大量 `/product/details*.html`。
- 落库 49 篇中：约 **4** 条资讯详情、**24** 条产品页、其余其它——**卡片门户 + 全站链污染** 明显。
- **全部 49 条 title 都是「产品及解决方案」**，标题抽取完全失效。
- **结论**：卡片式列表「能打开、能抽到少数资讯详情」，但默认启发式会把产品卡片一并当新闻；要加路径前缀过滤（仅 `aboutus/news/`）并处理 JS 分页。

## 3. 对「能抓到的网页范围有多大」的回答

| 维度 | 现状（本实验） |
|------|----------------|
| 入口列表页 | 三家均可 HTTP 打开 |
| 第一页新闻链 | 平安：**可覆盖**；大悦城/神州数码：入口不是纯列表，**有效新闻链很少** |
| 历史翻页 | **均未覆盖**（平安有静态分页未跟；神州数码疑似 JS 分页） |
| 正文可用性 | 平安相对最好；大悦城/神州数码噪声与标题问题严重 |
| 适合直接入库？ | 仅平安「新闻路径」子集可考虑；另两家需改规则后再谈范围 |

## 4. 改进建议（下一轮实验可验证）

1. 增加 **分页跟随**（至少支持平安 `index_N.shtml` 静态分页，设最大页数）。
2. 按站点配置 **URL 白名单/黑名单**（平安：优先 `/about/news/`；神州数码：仅 `aboutus/news/details`；大悦城：先人工确认真实列表 URL）。
3. 修复 **标题抽取**：优先列表锚文本 / `og:title` / 正文 H1，避免站点公共标题。
4. 对门户页增加「列表页发现」步骤，而不是把门户当列表。
