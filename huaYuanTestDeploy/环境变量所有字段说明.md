# 公司发布平台环境变量（华院 Agent + 采集）

> 核对时间：2026-09-21（相对当前 `config/model_providers.yaml`、华院 flow、`backend/app/config.py`）。  
> 结论：**镜像构建不打密钥**（`.dockerignore` 已排除 `.env`）；发布时按下面注入。  
> 华院 chat / portrait / radar 的 `provider` 已全部改为 `huayuan`，密钥是 **`HUAYUAN_API_KEY`**。继续只配 `DOUBAO_API_KEY` / `OPENAI_API_KEY` 会导致 LLM 拿到空 key。

## Agent `unidt-exhibition-opportunity-py-agent`

容器端口：`8000`  
K8s 服务名：`exhibition-opportunity-agent`（展厅 Java 的 `AGENT_BASE_URL` 指向它）

### 现网必配（K8s）

```text
ENABLE_DATABASE=false
LANGFUSE_ENABLED=false
HUAYUAN_API_KEY=<公司网关 key>
ANY_SEARCH_API_KEY=<AnySearch key>
# 可选。多把 key 英文逗号分隔；写了就只用这份，不再读 ANY_SEARCH_API_KEY。
# ANY_SEARCH_API_KEYS=<key_a>,<key_b>
BO_CHA_APIKEY=<博查 key>
NEWS_CRAWL_ENABLED=true
ANTHROPIC_AUTH_TOKEN=<可与 HUAYUAN_API_KEY 同一把>
```

| 变量 | 作用 |
|------|------|
| `ENABLE_DATABASE` | 华院最小部署不连本仓 Postgres，保持 `false`。镜像 Dockerfile 已有同名默认值，发布页再写一次更稳妥。 |
| `LANGFUSE_ENABLED` | 可观测性，现网关。镜像未装 `langfuse` 包。 |
| `HUAYUAN_API_KEY` | **华院 LLM 主密钥**。`config/model_providers.yaml` 的 `provider: huayuan` 读 `${HUAYUAN_API_KEY}`；chat / portrait / radar 三条 flow 都是 `provider: huayuan`。 |
| `ANY_SEARCH_API_KEY` | 雷达事件联网检索的单把 key。未配 `ANY_SEARCH_API_KEYS` 时使用。两处都空时工具直接失败，不再匿名调用。 |
| `ANY_SEARCH_API_KEYS` | 可选。英文逗号分隔的 key 池，按顺序故障转移（401/402/403 换下一把）。非空时覆盖单 key。 |
| `BO_CHA_APIKEY` | 博查 Web Search。无 key 时工具跳过，雷达质量下降。 |
| `NEWS_CRAWL_ENABLED` | 代码默认 `false`。展厅会调 `/api/v1/huayuan/news-url-crawl`，现网必须 `true`。 |
| `ANTHROPIC_AUTH_TOKEN` | 新闻抓取 Claude Agent SDK 凭证（Anthropic 兼容协议）。可与 `HUAYUAN_API_KEY` 同一把公司网关 key。 |

说明：

- **不要再配** `DOUBAO_API_KEY` / `OPENAI_API_KEY` 作为华院主模型。
- `ANTHROPIC_BASE_URL` / `ANTHROPIC_MODEL` 代码已有缺省（`https://ai-api.unidtai.com/openapi/llm/anthropic`、`deepseek/deepseek-v4.1-flash`），发布页可不写。`NEWS_CRAWL_ENABLED` 没有凭证时该接口仍返回 503。

### 知识库召回（画像 / 雷达评分建议配）

当前 `huayuan_portrait_agent` / `huayuan_radar_event_agent` 的 gather 会走 **Milvus 向量召回**（`radar_company_news_chunk`）。镜像已装 `pymilvus`。不配则召回失败并降级，接口仍能打分，但没有知识库证据。

```text
HUAYUAN_API_URL_embeddings=https://ai-api.unidtai.com/openapi/llm/compatible-mode/v1/embeddings
MILVUS_URI=<Milvus 地址，如 http://host:19530>
MILVUS_USER=
MILVUS_PASSWORD=
MILVUS_DB_NAME=exhibition_test
MILVUS_COLLECTION=radar_company_news_chunk
```

| 变量 | 作用 |
|------|------|
| `HUAYUAN_API_URL_embeddings` | 公司网关 embedding **完整端点**（必须以 `/embeddings` 结尾）。与 LLM 共用 `HUAYUAN_API_KEY`。`EMBEDDING_MODEL` 默认 `unidt/embedding-bge-m3`，一般不用另配。 |
| `MILVUS_URI` / `MILVUS_USER` / `MILVUS_PASSWORD` | 向量库连接。`MILVUS_DB_NAME` 是**库名**（现网 `exhibition_test`），不是 collection 名。 |
| `MILVUS_COLLECTION` | 默认 `radar_company_news_chunk`（V2 一行一 chunk）。 |

按需拉全文（工具 `load_news_document`）还要读 exhibition MySQL 的 `radar_company_news_document`。**当前 Agent 镜像未装 `pymysql`**，即使配了 `EXHIBITION_MYSQL_*` 也会失败并降级；等镜像补依赖后再加：

```text
EXHIBITION_MYSQL_HOST=<与采集同一套 exhibition MySQL>
EXHIBITION_MYSQL_PORT=3306
EXHIBITION_MYSQL_USER=
EXHIBITION_MYSQL_PASSWORD=
EXHIBITION_MYSQL_DB=unidt_exhibition
```

L2 发现+正文**写入**（`radar_kb`）代码默认 **关**（`RADAR_KB_WORKER_IN_APP=false`）。

`radar_kb` 是本仓库里的**知识库写脚本包**（发现列表、抓正文、embedding、写入 MySQL/Milvus），和对外 HTTP API 不是一回事。`pymysql` 是它连 exhibition MySQL 用的驱动。当前 Agent 镜像只 COPY 了 `backend/` + 华院 flow，**没有** `radar_kb/`，`requirements-huayuan.txt` 也**故意没装** `pymysql`（当时按纯 API 裁的）。

所以：开关打开 = FastAPI 进程里 `import radar_kb`。镜像里没有这两样，开了只会启动失败打日志，写链路并不会真跑。

| 阶段 | 怎么配 |
|------|--------|
| 现在发 test（仅 API） | 发布页**不必写**这个变量；保持关。 |
| 以后 test 要跑写入，且挂在 **同一个 Agent 容器** | 才需要改 Dockerfile：COPY `radar_kb/`，并把 `pymysql` 加进 `requirements-huayuan.txt`。然后只在 **test 发布页** 设 `RADAR_KB_WORKER_IN_APP=true`，并配 MySQL。本地 `.env` 继续关。 |
| 以后 test 要跑写入，但 **单独一个进程/容器**（更干净） | **不必**打进 Agent 镜像。保持开关 false，另起 `python -m radar_kb`（或独立 Worker 镜像）。 |

不要把本地默认改成 true：本机一开 uvicorn 就会对 exhibition 库抓站，也容易和独立进程双开、抢同一批任务。

### 一般不必配

| 变量 | 说明 |
|------|------|
| `PROMPT_SOURCE_MODE` | 镜像 Dockerfile 里写了 `local`，Python `Settings` **不读这个键**，发布页可省略。 |
| `ANTHROPIC_BASE_URL` / `ANTHROPIC_MODEL` | 有代码缺省；与 LLM 的 `compatible-mode/v1` **不是同一条路径**。 |
| `HUAYUAN_DOCUMENT_TOOL_BASE_URL` | 旧画像 `load_document_by_file_id` 回调展厅 HTTP 才用。现网 portrait / radar 走 Milvus + `load_news_document`，请求体一般也不再依赖它。 |
| `DOUBAO_API_KEY` / `OPENAI_API_KEY` / `DEEPSEEK_API_KEY` | 华院 flow 已切走。 |
| `DATABASE_URL` | `ENABLE_DATABASE=false` 时不连本仓 Postgres。 |
| `RADAR_KB_WORKER_IN_APP` | 默认 false。现在发 test 不用写；以后要进程内写入再只改 test 发布页。 |
| `RADAR_KB_*` 调参 | 写入未打开时配了也不会跑。 |

## 采集 `unidt-exhibition-opportunity-py-crawl`

无 HTTP 端口。启动：`python -m radar_crawl`。

### 现网必配

```text
RADAR_WORKER_MODE=all
RADAR_DB_HOST=<exhibition MySQL>
RADAR_DB_PORT=3306
RADAR_DB_NAME=unidt_exhibition
RADAR_DB_USER=
RADAR_DB_PASSWORD=
RADAR_CNINFO_FETCH_PDF=1
```

**本镜像不调 LLM，不需要 `HUAYUAN_API_KEY`。**

`RADAR_POLL_INTERVAL_SEC`（默认 60）、`RADAR_PDF_CONCURRENCY`（默认 3）等有代码缺省，发布页可不写。

## 一句话对照

| 服务 | 发布时要配的环境变量 |
|------|----------------------|
| Agent | `HUAYUAN_API_KEY` + `ANY_SEARCH_API_KEY`（多把 key 时改为 `ANY_SEARCH_API_KEYS`）+ `BO_CHA_APIKEY` + `NEWS_CRAWL_ENABLED` + `ANTHROPIC_AUTH_TOKEN`；知识库召回再加 embedding 端点 + Milvus。写入默认关，以后要跑再设 `RADAR_KB_WORKER_IN_APP=true` |
| 采集 | `RADAR_DB_*`（无模型 key） |
| 展厅 Java | `AGENT_BASE_URL=http://exhibition-opportunity-agent:8000`（在 exhibition 仓库配） |
