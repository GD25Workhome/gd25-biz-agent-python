# 实验 260915-1:SDK 0.2.152 签名 smoke

## 背景

`company_claude_cral/00-结论摘要.md` §3.1 留下的工程前提:
"claude-agent-sdk 0.x 迭代快,`allowed_tools`/`setting_sources` 等签名可能已变,
动手前先钉版本并跑通一个最小 smoke。"

生产代码 `backend/domain/news_crawl/agent_runner.py` 是按实验时代
(CLI v2.1.113) 的 API 写的,当前开发环境装的是 **SDK 0.2.152 + CLI 2.1.272**。
76 个单测全部通过,但它们 stub 掉了 runner,**从未真正实例化过 ClaudeAgentOptions**。

## 验证点

1. `ClaudeAgentOptions` 接受 `agent_runner.py` 用到的全部参数
   (system_prompt / model / env / mcp_servers / allowed_tools / disallowed_tools /
   permission_mode / max_turns / skills / setting_sources),构造不抛错
2. 真起一次 CLI 子进程跑最小对话,收到正常 ResultMessage

## 结论(2026-09-15)

1. ✅ **签名兼容**:`ClaudeAgentOptions` 全参数构造通过,SDK 0.2.152 与生产代码兼容
2. ✅ **CLI 子进程跑通**:最小对话 success,turns=1,cost=$0.10
3. 🐛 **SDK 坑**:`env=None` 会在 connect 时抛
   `TypeError: 'NoneType' object is not a mapping`(SDK 内部做 `**options.env`),
   必须传 dict。生产代码 `_sdk_env()` 恒返回 dict,安全。
4. ⚠️ 本机 shell 的 `ANTHROPIC_MODEL=deepseek-v4-pro` 会让 CLI 打
   `unrecognized_model` 警告,但网关仍能跑通(实测 success)。
   .env.example 里生产配置用 `deepseek/deepseek-v4.1-flash`。
