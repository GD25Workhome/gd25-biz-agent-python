> 分支：`huayuan/v2.1-260916`  
> 目标：剪掉华院部署不需要的依赖；本文件先把「保留 / 可删 / 边界」说清楚。  
> 范围：方案 A（瘦身裁剪），**不做**主库 PG→MySQL 全量迁移。

---

## 1. 结论先行

| 问题 | 答案 |
|---|---|
| 华院镜像实际装什么？ | **`requirements-huayuan.txt`**（见 `Dockerfile`） |
| 全量 `requirements.txt` 是什么？ | 历史医疗/RAG/AutoGen 大包，**华院镜像不用它** |
| 主库 PostgreSQL / pgvector？ | **华院不需要**；`ENABLE_DATABASE=false` 已是默认 |
| 关系数据用什么？ | **exhibition MySQL**（`pymysql`），仅 `news_content_worker` / `radar_crawl` |
| 向量用什么？ | **Milvus**（`pymilvus`），雷达检索 + worker 写入 |
| 代码耦合是否已解？ | 四耦合点（registry / tools / routes / DB 可选）**已在本分支解开** |

**本阶段动作**：把依赖边界写死；后续若要「仓库级」也瘦身，再从全量 `requirements.txt` 物理删除可删包（需确认本地医疗开发是否还要）。

## 4. 华院可删 / 不应进华院镜像（全量 `requirements.txt` 中）

| 包 | 原用途 | 华院处置 |
|---|---|---|
| **psycopg[binary] / psycopg-pool** | 主库 PostgreSQL | **删**（华院不连主库） |
| **pgvector** | 医疗 RAG 向量列 | **删**（改用已有 Milvus） |
| **sqlalchemy / alembic** | 主库 ORM / 迁移 | **删**（华院镜像 Dockerfile 已 rm `infrastructure/database`） |
| **sentence-transformers**（+ torch） | 本地 embedding / RAG | **删**（体积最大） |
| **volcengine-python-sdk[ark]** | 豆包 Embedding SDK | **删**（华院用网关 HTTP embedding） |
| **pandas / openpyxl** | RAG Excel 导入 | **删** |
| **autogen-agentchat / autogen-core / autogen-ext** | AutoGen Team 节点 | **删**（registry 已不注册） |
| **langchain-text-splitters** | RAG 切分 | **删** |
| **python-ulid** | 主库 ID | **删** |
| **aiosqlite** | 测试库 | **删**（仅开发测试） |
| pytest* / black / ruff / mypy | 开发工具 | **不进运行镜像** |
| langfuse | 可观测 | 镜像已默认关；可继续不装 |

### worker 专用（华院 API 镜像可不装，worker 进程要装）

| 包 | 用途 |
|---|---|
| pymysql / cryptography | exhibition MySQL |
| pymilvus | 写入向量 |
| （复用）httpx / pydantic / claude-agent-sdk 等 | embedding + Agent 兜底 |

> 缺口：`requirements-huayuan.txt` **没有** `pymysql`/`cryptography`——对 **API 镜像正确**；若用同一镜像跑 worker，会缺驱动。后续可加 `requirements-news-worker.txt`。

## 5. 与「PG→MySQL / pgvector→Milvus」的关系

| 诉求 | 方案 A 做法 |
|---|---|
| 去掉 PG 依赖 | **不迁库**：关掉主库 + 依赖不装 `psycopg`/`pgvector` |
| 向量用 Milvus | **已落地**雷达线；医疗 pgvector 链路不进华院镜像即可 |
| exhibition MySQL | **已是**写链路真相源，不是把 gd25 主库改成 MySQL |
